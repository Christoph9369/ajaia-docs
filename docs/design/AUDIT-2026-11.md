# Design audit, 2026-11 (report only, nothing fixed)

**Scope and method (be aware of the limits):** Impeccable `detect` (v4.8.2) on `src/`, on `/login` rendered in a headless browser, and on saved HTML of `/documents` and `/documents/[id]` as alice (static analysis, so Tailwind-computed styles may be under-resolved). Plus a manual read of `globals.css`, `components/ui.tsx`, and a grep of motion code. I did **not** run Impeccable's interactive `/audit` or Emil's `review-animations` flows, and did not take screenshots, so there are no numeric scores. The app has no `docs/design/` brand rules; `PRODUCT.md` records only what the code shows.

## Verdict: does it look AI-generated?
No, not in the usual sense. It is plain and restrained: neutral canvas, one blue accent, Inter + a serif for document body, no gradients, glows, gradient text, decorative backgrounds or emoji. The detector found no slop patterns beyond one blockquote border. Weak spots are accessibility details and a flat type scale on the dashboard, not generic styling.

## Findings
"Fits our brand?" is judged against the tokens in `globals.css` and `PRODUCT.md` (no formal brand doc exists).

## What works well
- Consistent token set, one accent, calm Operate-style layout.
- Visible save state, role badges, and `role="alert"` errors (27 aria/role attributes in `src/`).
- Focus ring defined globally (`:focus-visible`).
- Almost no motion, which suits a daily-use editor.

## Anything a skill wants that breaks project rules
None encountered. Watch for: Impeccable may suggest new fonts or a bolder direction (finding 8 touches this), and Emil's skills assume Framer Motion/CSS-spring patterns. CLAUDE.md/PRODUCT.md say: stay on Tailwind, no animation library, no new direction without approval.
