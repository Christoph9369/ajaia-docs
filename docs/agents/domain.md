# Domain Docs

How the engineering skills should consume this repo's domain documentation. Single-context repo.

## Before exploring, read these

- `README.md`: features, demo accounts, scripts.
- `ARCHITECTURE.md`: stack, data model, permission and conflict design, deliberate cuts.
- `GLOSSARY.md` at the repo root, if it exists.
- `docs/adr/`, if it exists: read ADRs that touch the area you are about to change.

If a file does not exist, proceed silently. Do not suggest creating it up front.

## Use the glossary's vocabulary

Use terms as defined in `GLOSSARY.md` and `ARCHITECTURE.md` (document, owner, editor, viewer, share, version, conflict). If your output contradicts an ADR, say so explicitly instead of overriding it.
